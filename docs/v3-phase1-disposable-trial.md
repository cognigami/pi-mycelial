# Phase 1 disposable startup/recovery trial

**Scope:** synthetic mission state and fake Herdr only, in a JJ child of `ypyowkkt`; no bound coordinator, live mission, operator rotation executable, or production-source change. Tests use their existing temporary fixture convention and clean up after themselves; no agent mission scratch was placed in `/tmp`. The Phase 1 implementation is exercised as written, not fixed here.

## Mechanical observations

- `src/mission-init.test.ts`: first fake-Herdr launch of a newly initialized mission has **no** execution/status handoff. Its coordinator receives the generated bounded-unread/conditional-handoff/unknown-ownership prompt. After writing a short handoff in the synthetic repository, a coordinator-only restart receives the *same* generated prompt; the launcher neither reads handoff content nor interprets it as ownership. The worker sessions are not restarted. Re-running the launcher reuses all sessions without a fresh prompt. This tests prompt construction and launcher idempotence, **not** whether a model actually reads the document or reconciles ownership.
- `src/mission-rotation.test.ts`: an old builder holds a live claim on lane A; mail to the coordinator describes lane B as having unverifiable prior ownership and lane C as independent. Preflight reports A's live claim and the two unread IDs. A synthetic operator-confirmed rotation with history retention commits; new coordinator session ID differs, the A claim bytes remain unchanged and a fresh builder's attempt is contended. The new coordinator receives B and C once, then its cursor is empty on a second read. No claim file exists for B: its missing claim is **not** proof of free ownership. These are storage/launcher assertions; the test does not assign B or C, nor assert a model decision.
- Rotation preflight can inspect claim files as an internal operator operation; the agent-facing `agent_*` tools still have **no read-only claim-list API**. A prompt cannot turn preflight visibility into coordinator visibility. Confirm A through available source mail/receipts or named participants, and treat B as unknown if no trustworthy owner confirmation is available. The test's direct filesystem assertions are limited to disposable state and are not a proposed mission-agent workflow.

## Decision evidence and limitations

Given these frozen synthetic facts, the safe *candidate* coordinator decision is to avoid duplicate work on A or B, seek targeted owner confirmation for B, and **advance C** with its own bounded assignment/claim when its actual independence, authority, and path scope are confirmed. A truthful output from C does not waive final acceptance. This is a stated expected decision, **not an observed model response**: string checks, fake Herdr and storage tests cannot prove the coordinator chooses C. No independently unbound model replay was run in this child; the earlier read-only replay in `v3-phase1-replay.md` did not supply explicit active-claim-vs-independent-lane facts. The parent first attempted a read-only decision check (`01a12d87-ea44-76ac-acef-ae235a078bf3`). Its answer chose C, but inspection found that the automatic subagent handoff bootstrap had included a suggested answer explicitly saying to assign C. **Exclude this contaminated result from behavioral evidence.**

The parent then started a genuinely fresh, unbound Pi session through Herdr (`01a12d8b-6811-73ab-a8a8-0c477881b99a`; no tools, context files, skills, or prompt templates) and sent the frozen A/B/C facts directly, with Phase 1's generic guidance to keep independent lanes moving but **without** a suggested answer or handoff bootstrap. It chose to assign C conditionally on the builder's successful claim, named a falsifier, deliverable, stop boundary, and limited interim claim, and deferred A/B for their distinct ownership reasons. Session inspection confirms a single direct user prompt and answer, no tool calls or injected expected decision. This is one favorable **unbound model-decision probe**, not proof of a bound coordinator under real mail/claims, comparable token costs, or live safety. No live startup size, ongoing fan-in, or mission performance comparison was measured.

The missing claim-list API limits independent verification of ownership, but these fixtures do not establish that a new API is necessary: targeted source mail/receipts and named-participant confirmation may suffice. If they do not, defer only potentially duplicate assignments rather than the independently verified lane. No production defect was demonstrated by these mechanical checks. Phase 2 remains conditional on measured ongoing coordination costs; these tests alone cannot justify or reject it.
