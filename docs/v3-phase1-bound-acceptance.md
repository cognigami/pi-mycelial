# Phase 1 bound disposable acceptance (2026-10-12)

**Scope:** installed Phase 1 with `just install` at an operator-provided pause (195 tests passed), then used only mission `v3p1-accept-f04578a3` in an isolated, read-only synthetic repository. The fixture's toy value was 5; it was not market data. No Benny mission document, launcher, broker, production code, or mission state was changed. Herdr later showed Benny agents still live but idle; they were not rotated or restarted. Both disposable rotations were performed by the operator with `--save-history`, after the disposable Pi processes were stopped. Mission state was handled by `agent_*` inside bound sessions; this parent used Herdr to start/stop sessions and the operator's reported rotation output as evidence.

## First rotation: independent lane with unknown ownership

The initial coordinator sent builder-1 a scoped A request. Builder-1 claimed it, while B's owner was unknown and a short repository handoff pointed to an independent, read-only C fixture check. Two B/C messages were sent while the coordinator was stopped. The operator's first rotation retained four session histories and reported both messages unread. It did **not** warn of a live A claim: the five-minute lease had expired before rotation. This first run cannot establish live-claim preservation.

Fresh coordinator session `01a12db9-877f-7371-b0ce-6bacaca0f17f` used the handoff, roster, source goal and bounded unread mail. It deferred duplicate A/B assignments, asked for targeted A/B ownership evidence, and assigned builder-3 a bounded, falsifiable C request. Builder-3 claimed the request, read `data/fixture-input.md`, reported that toy value 5 is positive with a fixture-only interim claim, released it, and stopped. The coordinator accepted that narrow result without final mission acceptance. No fixture files were edited.

## Second rotation: live A claim and stale handoff

In the first rotated generation, the coordinator authorized builder-1 to take over the original A task solely for this test. Its normal `agent_task_claim` returned `taken-over` with a requested 3,600,000 ms lease; no research was performed. After stopping the disposable agents, the operator's second rotation preflight explicitly warned: `01M4PSQQQ2DCSDWRC4882TEFAF` was still exclusively owned by old-session builder-1 until `2026-10-12T02:32:13.022Z`, **with no claim transfer**. Rotation committed and retained the four old histories.

The existing handoff was intentionally stale about C (it still called C unassigned). Fresh coordinator session `01a12dbe-b688-79b0-b495-f70d6717698e` read the short handoff, roster and bounded unread mail, then performed one targeted bounded replay (20-message limit) to verify the prior C report. It read the approved goal and fixture, accepted the already-reported C diagnostic without reassigning it, and kept final acceptance open. For A it did not inherit, claim, or duplicate the old-session task; it requested status/release evidence from builder-1. It treated B's owner as unknown and requested evidence from builder-2 rather than assigning B work. Notifications to stopped participants failed; mail was durable, and permitted `agent_wake` retries failed. No source or mission controls were edited. The coordinator was then stopped.

## Size, limitations, decision

From retained Pi JSONL usage records, the **first coordinator reconciliation turn** went from 16,470 to 21,132 reported tokens per request over about 56 seconds; the **second**, from 16,530 to 23,757 over about 85 seconds. These figures are per-request usage, **not context occupancy**, a controlled latency comparison, or mission-wide cost. The fixture is tiny; Benny's historical 89,952-token request cannot be used as a like-for-like baseline. The second turn's bounded replay and stale-handoff verification cost additional context but did not entail an unbounded history reconstruction. A read-only claim-list tool remains absent; the coordinator used source mail and deferred uncertain ownership. No builder attempted a conflicting post-rotation A claim in this bound run; the synthetic rotation test covers that storage behavior.

This is favorable **bound disposable** evidence for the Phase 1 decision rule and rotation safety, not proof of sustained context/cost improvement in Benny or another long-running mission. Phase 2 staff coordination is not justified on this evidence. Keep it conditional on a demonstrated Phase 1 failure; a narrower ownership-visibility change should likewise require a recurring blocked case. Do not install a global design/planning prompt on the strength of this fixture alone.
