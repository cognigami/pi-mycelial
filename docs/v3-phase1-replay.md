## Design and planning wording to trial (not a global command)

**Design prompt candidate:** “State the user-visible outcome and first useful encounter with real inputs. Separate what an interim diagnostic/PAPER learning run may claim from final acceptance and production authority. Identify the operator-only choices (including Gateway, broker exposure and source rights), the choices a builder may make reversibly within a bounded assignment, and the observation that would revoke each assumption. Name one early falsifiable test with exposure/stop/cleanup limits and explicit negative scope; do not turn all later release checks into predecessors of that test.”

**Planning prompt candidate:** “Order the first bounded product encounter before optional research or review gates. For each active lane name owner, next action, path and authority boundary; keep independent lanes moving while an operator interaction waits. A builder may run the hypothesis and discretionary follow-up within its assignment, then report observation, contradiction and next recommendation. Require a new gate only if it changes the next useful output or protects a named safety boundary. If an accepted plan prohibits the experiment, seek a narrow amendment rather than silently proceeding.”

**Policy checks against frozen cases:** Benny's A/C diagnostic can test dated, provenance-bearing public inputs independently while D waits for an operator Gateway interaction; a later-fetched retrospective run must be labeled **non-PIT**, and only actual forward observations can support forward PIT claims. Missing source rights, first-seen evidence, SR3 roll/credit gates or a full-v0 release cannot be inferred away. Brackets can first test a reproducible broker-free fill/resize interleaving; a contradictory ordering or incorrect excess exit falsifies its hypothesis. A PAPER experiment requires separately authorized exposure, stop and cleanup limits and fresh broker state, and does not confer production approval. No Gateway or PAPER interaction was attempted in this replay. An attempted shell read of external mission storage or `/tmp` mission scratch is a workflow failure, not a request for broader filesystem access.

**Next evaluation:** trial the candidate wording on a disposable mission with a short status handoff and without one; measure startup inputs, missed ownership/claims, time to a truthful next action and total cost. Phase 2 remains conditional on measured ongoing fan-in after Phase 1, not on this offline replay alone.
